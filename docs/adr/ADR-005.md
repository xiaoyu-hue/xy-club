# ADR-005：静态站多行业参考案例（查询参数切换 + 本地图片）

- 状态：已采纳（v1.8.0 起生效）
- 背景：
  本项目对外是一个"可复用的俱乐部官网模板"，README 反复强调"换一个俱乐部，只需改内容、换主题，不改代码"。但这句话目前**只有承诺，没有证据**：线上 GitHub Pages 预览站永远只展示 `defaults.js` 里的那一份陪玩俱乐部内容，访客看不到模板"变形"的能力。
  为了让人一眼看懂"这套模板能变成什么样"，需要让预览站在**不新增仓库、不新增部署**的前提下，支持站内切换多个**跨行业**的示范案例（咖啡店 / 律所 / SaaS / 摄影工作室）。
- 决策：
  1. **不改数据结构**：5 个案例全部用现有 8 种板块类型（`services` / `cards` / `testimonials` / `notice` / `faq` / `gallery` / `text` / `custom`）拼装，`db.json` 形状与 `defaults.js` 的 `DEFAULT_DB` 完全一致，因此**后台编辑器无需改造**即可编辑任意案例的内容。
  2. **案例内容为独立 JSON**：新增 `public/cases/*.json`（每个案例一份）+ `public/cases/manifest.json`（案例清单，供切换器读取）。这些 JSON 与 `content.json` 同构，不含任何凭据字段。
  3. **切换用查询参数，不用路径路由**：`?case=<id>`。原因是 GitHub Pages 对不存在的路径返回 404，SPA 式路径路由会直接失效；查询参数则天然可用，且不需要任何服务端改写规则（`_redirects` / `.htaccess`）。
  4. **兼容既有静态回退**：`public/content.json` **保留**，继续作为默认案例（XY俱乐部）的快照与最后兜底。`main.js` 的加载顺序变为：`/api/content`（Node）→ `cases/<id>.json`（静态，指定案例时）→ `./content.json`（静态，默认案例）→ 报错。**不破坏现有部署**。
  5. **切换器仅在静态模式显示**：只有 `<html class="static-mode">` 时渲染案例切换入口。Node 部署下后台是唯一内容源，多案例是纯静态站的演示特性，不干扰真实使用者。
  6. **图片落地本地**：案例配图从 Unsplash / Pexels 下载真实照片（两站均为免费商用授权），压缩后存入 `public/cases/images/`，**不做外站热链**。理由见下。
     > **v1.10.0 变更**：本条的实际执行已废弃——原台账无法自证授权（登记 URL 格式与 Unsplash 规则不符），16 张第三方图片已全部移除，改为**项目作者自有版权**作品。详见 [../IMAGE-AUDIT.md](../IMAGE-AUDIT.md)。决策原则（图片本地化、不外链）不变。
  7. **不新增依赖、不新增构建**：切换器为原生 JS（`public/js/case-switcher.js`），样式复用现有主题变量，无框架、无打包。
  8. **页脚统一声明**：静态站与案例页脚标注"示例内容，非真实企业信息"与图片来源授权，规避误导与法律风险。
  9. **内容层零真实企业信息（P1）**：案例企业名一律使用**明显虚构**且经查证不撞名的名称；电话用保留/占位格式（如 `400-000-0000`），地址用"XX市 XX 区 XX 路"式占位，Logo 一律 emoji，**不得出现任何真实企业名、真实门牌号、真实号码或真实品牌标识**。保护做在内容层，而非仅靠页脚声明。
  10. **图片授权可追溯（P2）**：每张图片在 `public/cases/CREDITS.md` 记录**原始下载 URL + License 名称 + 下载日期**，使授权可自证；选图须规避可识别的人物正脸与他人品牌 Logo（Unsplash / Pexels License 不覆盖肖像权与商标权）。
     > **v1.10.0 变更**：本条的**原则**（授权必须可自证）依然成立，且新增 `tests/credits.test.js` 强制执行；但**执行方式**已改为登记自有版权作品。原因是原方案暴露了一个真问题：台账可以写得好看却无法核验。教训是——**台账的价值不在于记录，而在于可验证**。
  11. **切换必须全量重渲染 + 主题重置（P3）**：切换案例后强制重渲染标题、导航、板块、CTA、页脚、弹窗数据，并重新应用该案例的 `theme`；防止上一个案例的全局状态残留（如"律所案例显示咖啡店微信"）。
  12. **无效 case id 优雅降级（P4）**：请求的 `?case=` 不存在或 `manifest` 缺失/解析失败时，自动回退默认案例，**不得白屏**；仅在全部失败时提示。
  13. **图片加载失败降级（P5）**：`gallery` 等图片元素绑定 `onerror`，加载失败时替换为 CSS 占位块，避免裂图。
  14. **切换不刷新页面 + 监听器清理（P6）**：切换用 `history.pushState` + 局部重渲染，支持浏览器前进/后退（`popstate`）；切换前清理上一次绑定的事件监听，避免监听器堆积与内存泄漏。
  15. **案例契约测试门禁（P7）**：`tests/cases.test.js` 强制校验每个案例 JSON 合法、板块类型在白名单内、`manifest` 与文件一一对应、**任何案例不得含 `adminPassword` 等凭据字段**。用测试锁死，不依赖人工记忆。
  16. **静态案例与服务端内容的隔离性保护（P8）**：`tests/case-isolation.test.js` 守住"两条内容路径永不交叉"这条隐式约定，分两层：
      - **静态检查**：`server.js` 不得出现 `cases` 路径引用；`DB_FILE` / `UPLOAD_DIR` 不得落在 `cases/` 下；`GET /api/content` 必须经 `readDB()` 而不直读文件；前端 `loadContent()` 中 `/api/content` 必须**先于** `loadCase()` 与 `content.json`
      - **行为检查**：真跑服务端，验证"改案例文件不影响 API 返回"、"服务端保存不写 `cases/`"、"服务端内容不泄漏进案例 JSON"
      - 必要性：两条路径的分离目前是**架构约定**（`server.js` 完全不认识 `cases/` 目录），没有代码强制。一旦被人无意打破，症状是"后台改了但页面不变"或"静态站覆盖真实内容"——难排查且无报错。该测试把约定转为可执行门禁。
- 理由：
  - 零新增依赖 / 零构建，与 ADR-003 完全一致；不改数据结构，与 ADR-002 一致（`DEFAULT_DB` 仍是唯一字段真源）。
  - 查询参数方案在 GitHub Pages 上零配置可用，是纯静态托管下唯一可靠的多视图方案。
  - 保留 `content.json` 使改动**向后兼容**：现有静态部署即使不更新也能继续工作，且 `scripts/build-static.js` 与 `static-build.test.js` 无需重写。
  - 图片本地化源于项目"零外部依赖、图片不经过第三方"的既有立场（README「数据与隐私」），同时规避国外 CDN 在国内的不稳定与被限流风险——演示站裂图比没有图更糟。
  - 决策 9–16 属**防御性保护**：跨行业示范内容天然带法律与信任风险（撞名、肖像权重用、误导访客），而多视图切换天然带状态污染与降级风险（白屏、裂图、监听器泄漏）。这些不是"加分项"，是**上线前的必要条件**——不满足则宁可不上。
- 代价：
  - **SEO 分不清**：5 个案例共用同一个 `index.html`，搜索引擎只会收录默认案例。演示用途可接受，需在文档写明。
  - **Node 部署下的割裂**：后台只能编辑 `data/db.json`（默认案例），案例 2–5 是只读静态 JSON。切换器需明确标注"演示案例"，文档需说明这是静态站特性。
  - **仓库体积增加**：16 张 WebP 图片，总计约 0.9MB（单图均 < 400KB）。
  - **文案非真实**：案例内容为示范文案，需靠页脚声明避免误认为真实企业。
  - **`main.js` 加载逻辑变复杂**：从两级回退变成四级，需补测试覆盖（`tests/cases.test.js`）。
  - **内容单向流动**：`content.json` 由 `data/db.json` 单向导出，反向无回流。在静态站手改 `content.json` 后再跑构建会被覆盖，属预期行为但易误判为"改动丢失"（已在 `docs/DEPLOY.md` 说明）。
- 演进：
  - 如需让后台也能编辑全部案例，须先解决"多份内容真源"问题（多 db 文件或 cases 目录写接口），这会冲击 ADR-002 的"单 JSON 真源"取舍，**必须先修订 ADR-002 与本 ADR 再动代码**。
  - 若将来需要真正的多页 SEO，应改为构建期为每个案例产出独立 HTML（引入构建步骤），届时须重估 ADR-003。
  - 案例数量若继续增长，`manifest.json` 可扩展 `tags` / `order` 字段支撑筛选与排序。
