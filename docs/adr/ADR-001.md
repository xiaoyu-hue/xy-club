# ADR-001：管理密码 scrypt 哈希（含 legacy 明文启动升级）

- 状态：已采纳（2026 起持续生效）
- 背景：后台为单管理员模式，原 `settings.adminPassword` 以明文存储于 `data/db.json`，一旦仓库或服务器文件泄露即直接暴露管理入口。
- 决策：
  1. 登录校验使用 Node 内置 `crypto.scrypt`（**无新增依赖**，不引入 bcrypt 之类），哈希落库格式为 `scrypt$<salt>$<key>`。
  2. 服务启动时若检测到 legacy 明文密码，自动就地升级为 scrypt 哈希；登录命中明文时也顺手升级。
  3. 忘记密码的唯一正规途径是 `node scripts/reset-password.js 新密码`，禁止手改 `db.json` 明文。
  4. 同一 IP 连续 5 次密码错误后锁定 5 分钟（HTTP 429），计数存内存，重启即清空。
- 理由：零新增依赖换来零供应链攻击面；哈希避免在磁盘上明文留存口令；启动/登录双路径升级保证旧数据无痛迁移。
- 代价：
  - 单密码单管理员，无多用户 / 角色；会话存内存，重启即登出。
  - 无 CSRF 防护；scrypt 成本参数（盐长度 / 迭代）固化在代码，调参需改实现。
  - 内存会话在水平扩容时无法共享（与"单进程"约束同源）。
- 演进：如需可插拔 KDF、提高 scrypt 成本或加用户体系，先改本 ADR 再改代码；多副本部署前必须先解决会话与限流的外部化。
