# ADR-002：本地 JSON 文件为唯一数据真源（无数据库 / 单进程）

- 状态：已采纳（2026 起持续生效）
- 背景：本项目的本质是"可复用的俱乐部官网模板"，作者无编程基础，需要"改完内容刷新即见"，并且要能纯静态托管（GitHub Pages 等无 Node 进程的环境）。
- 决策：
  1. 全部内容与设置存于单个 `data/db.json`（形状由 `defaults.js` 的 `DEFAULT_DB` 定义），**无数据库**。
  2. 首次启动若文件缺失，由 `defaults.js` 生成出厂内容；读写为全量 JSON。
  3. 官网与后台共用同一份 `db.json`，后台改什么前台刷新即是什么——无缓存层、无重新构建。
  4. 单进程部署；`data/` 与 `public/uploads/` 必须落在持久卷上。
- 理由：零运维、文件可 `gitignore`、易备份与迁移；配置导出时把 `/uploads/*` 内联成 data URI 让 JSON 自包含，导入时还原为真实文件，搬站不裂图。
- 代价：
  - 不支持多副本 / 并发写（JSON 全量读写会冲突），违背"单进程"即数据风险。
  - 大站点存在 I/O 放大（每次写都重写整文件）；内存会话重启即丢。
  - 字段缺失需向后兼容默认值，否则旧数据可能"凭空消失"。
- 演进：如规模确实需要，可评估 SQLite / 嵌入式存储，但必须先过 DECISION_REVIEW（会冲击"零依赖 / 单进程"取舍）；迁移须保留 `DEFAULT_DB` 作为字段真源。
