# ADR-003：零构建静态前端 + Node/Express 服务端（无前端框架）

- 状态：已采纳（2026 起持续生效）
- 背景：作者无编程基础，目标用户是"不懂代码但想拥有好看、好改、好部署官网"的俱乐部运营者；模板需可被访客 DevTools 直接看到全部源码（天然开源）。
- 决策：
  1. 原生 HTML / CSS / 原生 JS，**零前端框架、零打包器、零构建步骤**。
  2. `express` 是唯一的运行时依赖；`server.js` 同时负责静态托管 `public/` 与提供 REST API（`/api/content`、`/api/login`、`/api/upload` 等）。
  3. 四套主题不是多套 CSS，而是同一套 CSS + 4 组变量（`html[data-theme="..."]`）；切换只改一个属性，所有组件引用变量、不硬编码颜色。
  4. 纯静态托管环境下，前端 `fetch('/api/content')` 失败自动回退 `./content.json` 快照（由 `scripts/build-static.js` 生成，已剔除密码字段）。
- 理由：零供应链攻击面、零部署步骤、源码可读可改；主题变量约定让"新增组件不破版"有硬约束。
- 代价：
  - 无类型检查 / 无 tree-shaking / 无 sourcemap，首屏传输为未压缩代码。
  - 全局约定（主题变量、板块类型分支、API 路径）靠人与测试守护，无静态调用图保护。
  - 模块规模增长后"人肉顺序 / 命名约定"会失控。
- 演进：如需要更强工程化，优先引入浏览器原生 ESM（`type="module"`，仍是零构建），以 import 声明替代全局顺序 / 约定；禁止使用 React / Vue / Vite / Webpack 等（见 AGENTS 安全红线）。
