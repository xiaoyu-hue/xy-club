# ADR-004：契约固化式单元测试（node:test + 显式 glob，零新增依赖）

- 状态：已采纳（2026 起持续生效）
- 背景：CI 曾在 Node 18 红过——根因是 `--test-timeout` 是 Node 20+ 才有的 CLI 参数，Node 18 报 `bad option`；同时希望测试零新增依赖、跨 Node 18/20/22 表现一致。
- 决策：
  1. 用 Node 内置 `node --test`，显式 `tests/*.test.js`（shell 展开文件列表），**零新增依赖**。
  2. 测试隔离由 `tests/harness.js` 负责：临时目录 + `listen(0)` + `unref()`，绝不允许用例读写开发者真实的 `data/db.json`。
  3. "文档与代码一致"被固化成测试：`docs-sync.test.js` 校验 README API 表与路由一致；`contract-defaults.test.js` 校验渲染分支与 `DEFAULT_DB` 字段一致。
  4. E2E 为可选层（`e2e/run.js`，需要 `@playwright/test`）；未安装时 `npm run test:e2e` 自动跳过、退出 0，不算失败。
- 理由：零依赖、跨版本一致；把"文档不得超出实现""中英文档同步"等纪律落成可执行断言，CI 即暴露漂移。
- 代价：
  - 不能使用 vitest / jest 生态的插件与 UI。
  - 须回避 Node 18 不支持的新版 flag（如 `--test-timeout`）；靠 workflow 的 `timeout-minutes` 兜底超时。
- 演进：如测试数膨胀，可加分层目录但仍保持零依赖；E2E 如需常驻，再评估是否纳入 CI 门禁。
